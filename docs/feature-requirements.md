# 外贸 ERP 功能需求规格说明书

> 本文档基于客户提供的「功能清单」图（2026-08）逐条整理为可开发、可验收的需求规格。
> 原图以**红字**强调的功能点，本文统一标记 🔴 **P0**（本期必须交付的重点）。
> 实现基座：frappe `version-16` + erpnext `version-16` + 自定义 app `apps/general_erp`。
> 开发约定见 `README.md`：**所有新功能只写在 `general_erp`，不修改 frappe/erpnext 官方源码**。

## 1. 背景与现状

- 系统现状：站点 `general.erp.local` 已初始化，已建 1 个公司与会计科目表（95 个科目），业务数据（客户/商品/供应商）为空；自定义 app 目前仅有示例单据（Demo Note）。
- 系统定位：以**外贸**为核心的「CRM（线索/邮件/客户/营销/商机）+ ERP（销售/采购/生产/财务/库存）+ 统计 + 设置」一体化系统。
- 开发原则：优先复用官方 DocType + Custom Field / Print Format / Workflow 实现；确有必要才新建 DocType；扩展官方单据行为一律走 `hooks.py` 的 `doc_events` 钩子。

## 3. 总体设计

### 3.1 开发约定

- 新增 DocType、Workspace、Report、Web Form、钩子全部位于 `apps/general_erp/`，并在 `hooks.py` 注册。
- 结构变更后执行 `bench --site general.erp.local migrate`。
- 命名与代码风格遵循 `apps/general_erp/README.md` 既有约定。

### 3.2 全局横切需求

| 需求 | 说明 |
|---|---|
| 多币种与汇率 | 销售/采购/收付款单据支持多币种；汇率表维护每日汇率（复用 Currency Exchange 机制，实施时确认），统计统一折算本位币；工作台「今日汇率」与汇率记录复用同一数据源 |
| 中英文双语 | 界面中英双语（自定义 app `translations/` 维护）；外贸单据（PI/CI/PL）采用中英对照打印格式；用户可个人切换语言 |
| 权限与数据范围 | 三级数据范围：员工（本人）→ 主管（本部门下属）→ 管理员（全部）；通过 Role + User Permission + Department 实现 |
| 审批流 | Workflow 可配置：邮件发送、商机批复、采购订单、费用报销等 |
| 审计日志 | 登录日志、单据修改历史（frappe 内置 doc log）、邮件删除审核、公海流转记录均留痕 |
| 编号与模板 | 各单据 Number Series 编号；单证/报价单 Print Format；订单条款复用 Terms and Conditions |

### 3.3 优先级定义

- **P0**：原图红字功能点，本期必须交付。
- **P1**：主业务流核心能力（CRM 与标准 ERP 流程配置）。
- **P2**：聚合、分析与增强项。

## 4. 分模块详细需求

### 4.1 工作台

定位：员工登录首页，「任务 + 公告 + 数据」聚合视图；实现为 frappe Workbench + Number Card + Chart。

| 功能点 | 需求说明 | 实现方式 | 优先级 |
|---|---|---|---|
| 待处理任务 | 聚合当前用户待办：待审批（Workflow ToDo）、待审批邮件、待批复商机、待跟进客户等；显示数量，点击直达对应单据 | 自定义开发：待办聚合（基于 ToDo + 自定义视图） | P1 |
| 通知公告 | 公司级公告（系统通知、制度、节假日调整等），支持置顶与有效期 | 自定义开发：Announcement DocType + 工作台卡片 | P1 |
| 今日汇率 | 展示今日常用币种（USD/EUR/GBP 等）对本位币汇率，点击查看汇率记录 | 复用 Currency Exchange + Number Card | P1 |
| 日历 | 工作日历：节假日、工作检查、出运计划、跟进提醒，月/周视图 | 复用 Holiday + 日历视图 + 自定义事件 | P2 |
| 工作检查 | 周期性检查任务（如每周客户跟进质量检查）：主管布置、员工完成并反馈 | 自定义开发：工作检查 + 检查项 DocType，调度器提醒 | P2 |
| 员工工作情况表 | 各员工日/周工作量：跟进数、邮件收发数、报价数、新商机数等 | 自定义报表 | P2 |
| 公司业务数据 | 管理层关键指标：今日/本月外销订单额、收款额、报价数、毛利等 | 自定义 Number Card 组 | P1 |
| 员工业绩排行榜 | 按业绩（订单/收款额）、跟进量、邮件回复率等排名，周/月可切换 | 自定义报表（排行） | P2 |

### 4.2 线索

定位：网站询盘与新客户入口，经分发跟进后转为客户。

| 功能点 | 需求说明 | 实现方式 | 优先级 |
|---|---|---|---|
| 线索 | 线索记录：姓名、公司、邮箱、电话、来源、内容；状态流转（新建→跟进中→已转客户→无效）；可一键转客户 | 复用 Lead + 状态字段/Workflow | P1 |
| 分发跟踪 | 线索分发给员工：记录分发人、被分发人、时间；每条线索后续跟进状态可追溯 | 自定义开发：线索分发记录 + 跟踪视图 | P1 |
| 线索统计 | 按来源渠道/时间/分发人统计线索量与转化率 | 自定义报表 | P1 |
| 网站留言代码 | 提供可嵌入官网的表单代码（JS/iframe），访客提交询盘后系统自动生成线索；系统内提供可直接复制的代码片段 | 复用 frappe Web Form + 自定义「代码生成」页 | P1 |

### 4.3 邮件

定位：系统内邮件工作台（外贸邮件），覆盖「收—发—审批—建档—跟踪」全生命周期。自定义模块实现：邮箱经 IMAP/SMTP 接入，调度任务定时拉取（默认 5 分钟，可配置）。

| 功能点 | 需求说明 | 实现方式 | 优先级 |
|---|---|---|---|
| 待处理邮件 | 需要处理的邮件（待回复、待审批），显示数量与快捷入口 | 自定义开发：邮件消息 DocType + 文件夹视图 | P1 |
| 收件箱 | 收到的全部邮件（IMAP 同步），支持主题/发件人/时间搜索与筛选 | 同上 | P1 |
| 已发送 | 系统发出的邮件记录（含群发），含发送状态 | 同上（本地发送记录） | P1 |
| 草稿箱 | 邮件存草稿，可续编 | 同上 | P1 |
| 待审批邮件 | 外发邮件按规则触发审批（收件域、涉及报价/金额等）；审批通过后自动发出 | 自定义开发：邮件审批流（Workflow） | P1 |
| 已删除待审核 | 被删除邮件进入「已删除待审核」列表，审核人可复核并恢复 | 自定义开发：删除审核记录 | P2 |
| 邮箱设置 | 每位员工配置 IMAP/SMTP 邮箱、同步频率、签名；密码加密存储 | 自定义开发：邮箱账号 DocType + 定时拉取任务 | P1 |
| 下属邮件 | 主管可查看本部门下属邮箱（只读） | 数据范围权限 | P1 |
| 分发 | 邮件可分发给同事处理，分发记录可追溯 | 自定义开发：邮件分发操作 | P1 |
| 建档 | 邮件一键建档到客户/商机/产品：自动创建或关联对应记录并归档邮件 | 自定义开发：关联 Customer/Opportunity/Item | P1 |
| 归档 | 处理完的邮件按文件夹/客户维度归档 | 自定义开发 | P2 |
| 发送跟踪 | 外发邮件打开/点击状态跟踪（跟踪像素 + 点击跳转） | 自定义开发：跟踪服务 | P1 |
| 导入/导出 | 从外部系统导入邮件记录（如 EML）；邮件列表导出 Excel | 自定义开发 | P2 |

### 4.4 客户

定位：客户资产管理，「公海—私海」两级归属 + 跟进全程留痕。基于 Customer 扩展负责人（owner）与公海机制。

| 功能点 | 需求说明 | 实现方式 | 优先级 |
|---|---|---|---|
| 我的客户 | 当前用户为负责人的客户（owner = 本人） | Customer + owner 字段 + User Permission | P1 |
| 下属客户 | 主管查看本部门下属的客户列表（只读） | 数据范围（Department） | P1 |
| 公海客户 | 无私有归属的共享客户池；进入规则可配置（如 N 天无跟进自动回公海） | 自定义开发：公海机制（owner 置空 + 调度器） | P1 |
| 全部客户 | 当前用户按角色权限可见的客户列表 | 列表视图 | P1 |
| 热点客户 | 星标重点/高意向客户，独立视图 | 星标字段 + 列表筛选 | P1 |
| 客户跟进一览 | 全部客户跟进记录（电话/邮件/微信/拜访）：跟进时间、方式、内容、下次跟进时间 | 自定义开发：客户跟进 DocType | P1 |
| 导入/导出 | 客户 Excel 批量导入、列表导出 Excel | 复用导入/导出 | P1 |
| 360 度查看 | 客户详情聚合页：基本信息 + 跟进时间线 + 商机 + 报价 + 订单 + 收款 + 邮件 | 自定义开发：客户档案页（Dashboard/Portal） | P1 |
| 移交 | 客户负责人变更（跟进记录与业务关系随迁），保留移交日志 | 自定义开发：移交操作 + 日志 | P1 |
| 合并 | 重复客户合并：保留主记录，合并联系人/跟进/订单，源记录标记已合并 | 自定义开发：合并工具 | P2 |
| 共享 | 客户共享给指定同事（只读或共同负责），共享范围可控 | 自定义开发：共享记录 | P2 |
| 修改历史 | 客户文档字段级修改记录（谁在何时改了什么） | 复用内置文档日志 | P1 |
| 回收站 | 公海/无效客户回收至私海；已删除客户可恢复 | 自定义开发 + frappe 回收站 | P2 |
| 客户分析 | 客户维度分析：行业/区域/等级分布、公海进出、跟进转化漏斗 | 自定义报表/图表 | P2 |

### 4.5 营销

| 功能点 | 需求说明 | 实现方式 | 优先级 |

### 9.3 敏感数据保护

- 邮箱账号密码：仅存 hash/加密（自定义 Mail Account 的密码字段用 `Password` 类型，不回显）。
- 价格/汇率字段：按角色隐藏（9.2 矩阵中「只读/—」落到字段级）。
- 文件：OA 文件库按部门/共享范围授权，禁止跨部门读取。
- 网站留言代码（Web Form）：只暴露提交入口，不暴露列表查询；字段白名单 + 频控。

### 11.5 已知坑位备忘（后续开发注意）

1. Desk 页面 HTML 与 boot 数据均带缓存：boot 按用户缓存于 Redis `bootinfo`（`frappe/sessions.py`），Desk 页面缓存 `website_page::desk`；改磁贴/图标/字段后需 `frappe.cache.hdel("bootinfo", user)` + 清 `website_page::desk`，否则前端看到旧数据。

### 12.8 二期坑位备忘（后续开发注意）

1. `formatdate`/`format_date` 为 babel 格式：`YYYY-MM-DD` 中 DD=一年中第几天，会渲染成 "2026-08-232"；必须用 `yyyy-MM-dd`。
2. 打印模板为 Jinja 受限环境（safe_exec）：`frappe.defaults` 是函数（不能 `.get_global_default`），用 `frappe.db.get_default("company")`；`frappe.get_doc` 返回 dict（用 `.get()`）；`frappe.utils.formatdate/fmt_money` 可用。
3. 报表 JS 客户端：`frappe.datetime.monthstart()` / `frappe.utils.nowdate()` 不存在；月首用 `frappe.datetime.get_today().slice(0,8)+"01"`。报表 JS 从磁盘直读，无需 bench build。
4. v16 Sales Order 字段为 `customer`（非 `party_name`）。
5. 打印预览 URL：`/<DocType>/<name>?format=<格式名>`；`/printview?doctype=..` 返回 417。
6. 新 DocType 的 autoname 须为 `naming_series:naming_series`（只写 `naming_series` 不生效）；系列计数 key 是前缀（如 `EXP-2026-`）；hash 名单据不增计数，需手工补计数。
7. Workflow：Transition 的 `action` 是 Link→Workflow Action Master（须先建动作）；states 行 `allow_edit` 必填；states 行不可设 `update_field:"workflow_state"`（空 update_value 会清空状态字段并回退首个状态）。
8. migrate 孤儿检查：Workspace/Report 可放模块级路径；Workspace Sidebar / Desktop Icon 必须 app 级平铺文件（`<app_path>/workspace_sidebar|desktop_icon/<scrub>.json`），否则会被当孤儿删除。
9. 翻译字典缓存在 Redis（`MERGED_TRANSLATION_KEY`）：zh.csv 追加行后须 `frappe.translate.clear_cache()` 并清用户 bootinfo 缓存；左导航模块自动侧边栏的 DocType 标签在 boot 时走 `_(item.label)`，CSV 翻译即可生效。
