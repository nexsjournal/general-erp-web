## 四、真问题清单（全部经主控实测复核）
### P0（阻断）
1. **生产任务单审批流无人可操作**：workflow 提交=Manufacturing User、审批=Manufacturing Manager，7 个业务账号（sales/salesm/purchase/stock/accounts/boss/Admin）中仅 Administrator 持有这两个角色。→ 生产审批流对真实用户完全不可用。修复：给 boss1（或指定角色）加 Manufacturing Manager + 给生产操作员账号/角色加 Manufacturing User，或把 workflow 角色改成现有角色。

### P1（严重）
1. **客户 User Permission 隔离可被直连绕过**：列表层过滤生效（sales1 list 只见自己 2 个客户 ✓），但 sales1 直接 get_doc('汉堡机械设备 GmbH') 可读他人客户详情（frappe User Permission 不拦 by-name 直读）。UI 上输入 URL /app/customer/汉堡… 可打开。→ 需在 app 层 hook（has_permission 或 controller on_load）拦截，或接受为已知限制写进交付文档（建议拦截）。
2. **客户 360 页功能单薄**：渲染正常但只有"请选择一个客户"+查看，客户详情聚合（跟进时间线/商机/报价/订单/邮件）内容未充实（页面 body 仅 203 字符）。
3. **邮件中心页为占位**：body 421 字符，实际邮件操作仍在 /app/list/Mail，邮件中心页未做成聚合视图。

### P2（一般，登记待排期）
1. 空态数据 4 个列表：群发(Bulk Email)/公告(Announcement)/供应商仅 1/服务商 0——售前演示前需种子数据（供应商/服务商为空会显得产品没内容）。
2. workspace 中"系统参数"快捷入口指向不存在的路由（正确应为 System Parameter 列表）。
3. 需求缺口 5 报表：批次统计/员工统计/部门统计/出运日志/订单条目（出运日志可用 Communication/工作流注释近似；订单条目语义需与客户确认）。
4. 需求缺口：中英文配置（语言切换设置项未暴露）。
5. 群发效果分析无独立报表（数据字段已有，缺聚合）。
6. "公司数据报数"无独立落点（Dashboard 可覆盖，需与客户确认是否够）。
